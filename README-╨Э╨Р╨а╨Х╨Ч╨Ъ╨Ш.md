# AutoYouTube · Нарезки — исходники v0.1 (экспериментальная версия)

Это обновление к wersfad/AutoYouTube, а не отдельное приложение и не готовая APK.
В основной репозиторий ничего автоматически не отправлено.

## Что входит
- Вкладка «Нарезки» рядом со «Студией», без удаления существующих вкладок.
- Ссылка на опубликованное видео YouTube, Twitch VOD или текущий Twitch-эфир.
- Android foreground service с уведомлением и кнопкой остановки.
- Загрузка доступных фрагментов через yt-dlp, обработка FFmpeg на устройстве.
- Локальное распознавание Whisper Tiny, модель загружается один раз (~75 МБ), без сервера обработки.
- Эвристический отбор кандидатов по текстовым реакциям и звуковым пикам.
- MP4 720×1280, короткие фразы субтитров с простым появлением, обводкой и тенью.
- Обычный вертикальный crop с ручным выбором центра либо вебка сверху / игра снизу с ручной областью камеры.
- Учёт разобранных окон и экспортированных интервалов, чтобы повторный запуск того же источника не плодил те же клипы.
- Файлы сохраняются внутри приложения; «Сохранить / поделиться» вызывает системное меню Android.

## Логика Twitch
1. Получить сведения о текущем эфире.
2. Поискать среди недавних архивов запись, начавшуюся в пределах трёх минут от начала этого эфира. Предыдущий чужой эфир не считается текущим.
3. Если такая запись доступна, разобрать её хронологически, затем проверять новые доступные фрагменты.
4. Если текущая запись недоступна или невозможно надёжно сопоставить её с эфиром, явно сообщить об этом и записывать текущий поток с момента подключения.
5. В прямом режиме захват идёт непрерывно сегментами около двух минут, анализ не отключает захват между клипами. При чрезмерном отставании обработка останавливается с ошибкой, а не молча теряет очередь.
6. Если кандидатов нет — продолжать наблюдение, а не создавать случайные «хайлайты».
7. После достижения выбранного максимума клипов работа завершается.

Без сохранённой/доступной прошедшей части эфира восстановить прошлые моменты по ссылке нельзя. В прямом режиме моменты у границ сегментов могут терять контекст; склейка контекста между прямыми сегментами ещё не реализована. При появлении архива уже после запуска прямого режима автоматического переключения на него пока нет.

## Установка в существующий GitHub-репозиторий
1. Сделайте резервную копию репозитория или отдельную ветку `clips-mobile`.
2. Распакуйте этот архив и добавьте его содержимое в корень существующего AutoYouTube с сохранением путей. Папка `.github` скрытая — её тоже нужно загрузить. Не удаляйте старые `lib`, иконки и AutoYouTube.html.
3. Сохраните изменения (Commit). Обновлённый workflow запускает `flutter create`, затем `python3 tools/install_clips.py`, загружает исходники whisper.cpp v1.7.6 и собирает ARM64 APK.
4. GitHub → Actions → Build AutoYouTube APK → Artifacts → AutoYouTube-apk.
5. Установите APK на ARM64-телефон с Android 8+.
6. Во вкладке «Нарезки» сначала скачайте модель. Для первого теста используйте своё короткое публичное YouTube-видео, затем Twitch VOD, затем живой эфир.

Скрипт изменяет существующий HTML и Dart-мост точечно на этапе сборки. Старые функции не заменяются целиком. Если структура приложения изменена, интеграция остановится с явной ошибкой. Сборка только для Android ARM64; Android 8 — минимальная версия этого обновления.

## Что проверено здесь
- Синтаксис нового JavaScript и Python-установщика.
- Повторная установка не дублирует вкладку, мост и Gradle-настройки.
- JVM-тесты ClipLogic: допустимые домены, пересечения, отсутствие выдуманных клипов на тишине, поиск текстовой реакции, отсутствие пересечений отобранных клипов.
- Браузерные тесты на 390 и 1440 px: переключение источников, настройки кадра, отсутствие горизонтального переполнения, отсутствие имитации обработки в браузере.

## Что НЕ проверено и что ещё требует работы
- Android/Flutter APK здесь не собрана: в среде нет Flutter SDK и Android SDK, сетевой доступ к сборочным зависимостям недоступен.
- Нативный Android-модуль и JNI требуют реальной сборки в Actions и испытания на телефоне. Возможны ошибки интеграции/зависимостей — это первая версия исходников, а не подтверждённая рабочая сборка.
- Живой Twitch и скачивание YouTube не протестированы end-to-end. Доступность зависит от текущих ограничений платформ и версии yt-dlp. Приватные, платные и DRM-источники не поддерживаются; обхода ограничений нет.
- Нужны тесты наличия libass/libx264 в поставляемом FFmpeg, расположения шрифтов, кодеков и разрешений на целевом телефоне.
- Это пока не визуальное распознавание игровых событий и не полноценный редактор субтитров. Тайминги слов в коротких фразах приблизительные; автоматического трекинга вебки и покадрового выделения слов нет.
- Маленькая модель может ошибаться на шумном игровом звуке. Перед публикацией просматривайте клипы.
- Android ограничивает фоновые сервисы и может остановить приложение. Foreground service не гарантирует бесконечную работу; на Android 15+ у dataSync есть системный лимит времени. Учтены уведомление, остановка и сохранённый прогресс, но не автоматический перезапуск после убийства процесса.
- Нужны свободная память, заряд и охлаждение. Временные фрагменты расходуют трафик и место, хотя вручную исходник скачивать не нужно. При <400 МБ свободного места работа прекращается. Экспортированные ролики не удаляются автоматически.
- При установке APK поверх прежней нужна совместимая подпись. Исходный workflow не содержит постоянного release-keystore: не удаляйте приложение с ценными данными ради переустановки без резервной копии.

## Тесты
`python3 tools/test_install.py` — интеграционные проверки и JVM-тесты (нужны Node и JDK).
`python3 tools/test_install.py --logic-only` — только JVM-логика.
Предпросмотр HTML показывает интерфейс, но не может заменить Android-модуль и не генерирует фиктивные результаты.
